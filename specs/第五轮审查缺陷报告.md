## P1 — 已修复

### R5-1: `read_http_request` header 循环缺失 `buf.extend_from_slice`（第四轮回归）

**文件**: `src/http_mitm.rs:213-225`
**严重性**: P1
**状态**: ✅ 已修复

**问题**: 第四轮 R4-1 修复在 `read_http_request` header 循环中插入 64KB 大小检查时，意外丢失了 `buf.extend_from_slice(&tmp[..n])`。

`reader.read(&mut tmp)` 读到的数据从未追加到 `buf`，导致：
- `find_header_end(&buf)` 在空 buf 上永远返回 `None`
- 循环无法退出（直到 client 关闭连接 → `n == 0` → `buf.is_empty()` → 返回 `Ok(None)`）
- 所有 AI MITM 请求失效（`process_http` 收到 `None` 后退出，连接立即关闭）

**根因**: `read_http_request` 的 header 循环结构与 `stream_http_response` 不同。Response 函数中 `extend_from_slice` 在循环顶部、检查之前；Request 函数中 `extend_from_slice` 原本也在循环顶部，但 R4-1 修复时用大小检查**替换**了 extend 行，而非在其之前插入。

**修复**: 在大小检查之前恢复 `buf.extend_from_slice(&tmp[..n])`。
